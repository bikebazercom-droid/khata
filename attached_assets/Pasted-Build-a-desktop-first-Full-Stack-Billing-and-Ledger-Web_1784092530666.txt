1. DATABASE SCHEMA & BUSINESS LOGIC (SQLite):
- Create a `parties` table: id (TEXT PK), name (TEXT), phone (TEXT), role (TEXT: 'CUSTOMER' or 'SUPPLIER'), current_balance (DECIMAL), balance_type (TEXT: 'YOU_WILL_GET', 'YOU_WILL_GIVE', 'SETTLED'), due_date (TEXT), last_transaction (TEXT).
- Create a `ledger_entries` table: id (TEXT PK), party_id (TEXT FK), type (TEXT: 'YOU_GAVE' or 'YOU_GOT'), amount (DECIMAL), description (TEXT), bill_reference (TEXT), created_at (TEXT).
- Implement backend transaction logic: When a ledger entry is posted via 'POST /api/ledger', it must update the ledger and instantly recalculate the party's current_balance and balance_type:
  * For CUSTOMER: 'YOU_GAVE' (আপনি দিয়েছেন) increases what they owe us ('YOU_WILL_GET' / পাবেন). 'YOU_GOT' (আপনি পেয়েছেন) decreases it.
  * For SUPPLIER: 'YOU_GAVE' decreases what we owe them. 'YOU_GOT' increases what we owe them ('YOU_WILL_GIVE' / দেবেন).
